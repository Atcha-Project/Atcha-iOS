# AtchaV2 자동 검수 규약 — 사람 검수의 computer use 대체

> **성격**: 모든 Phase 프롬프트의 "사람 검수"를 이 규약의 **자동 검수**로 대체한다. 검수의 실행 주체는 사용자가 아니라 **실행 에이전트**다 — 에이전트가 computer use로 시뮬레이터를 직접 조작하고 스크린샷 증적으로 보고하며, 사용자는 조작이 아니라 증적을 검토한다.
> 적용 범위: Phase 13 이후 신규 프롬프트는 검수 절을 이 규약 기준("자동 검수" + "실기기 잔여")으로 작성한다. 기존 문서(마스터·LA 프롬프트)의 "사람 검수"도 재검수·잔여 검수(예: Phase 10~12 머지 전 검수)가 필요해지면 이 규약으로 수행한다.
> 충돌 시 **CLAUDE.md > [마스터 프롬프트](atcha-v2-master-prompt.md) > 개별 Phase 프롬프트 > 이 문서** 순. 작성일: 2026-08-23.

---

## 원칙

1. **시뮬레이터에서 재현 가능한 항목은 전부 에이전트가 직접 수행한다.** "사용자가 직접 확인해야 다음 진행" 대신 "에이전트가 수행·증적 보고해야 다음 진행"이 블로킹 게이트다.
2. **원리적으로 시뮬레이터 재현이 불가한 항목만 "실기기 잔여"로 분리**해 사용자에게 이관한다. 각 프롬프트의 검수 절은 `### 자동 검수 (블로킹)`과 `**실기기 잔여**` 두 부분으로 나눠 작성한다.
3. **실패를 숨기지 않는다** (마스터 진행 프로토콜 3 상속) — 기대와 다른 화면, 자동화 자체의 실패(플레이키·조작 불가)도 판정과 함께 그대로 보고한다. 자동화가 안 된다고 항목을 조용히 건너뛰지 않는다.
4. 검수는 **Debug(DEV) 구성**으로 수행한다 — DEV 전용 훅(데모 폴백·변경 시뮬레이터)이 검수의 재료다.

## 도구 스택 + 실측 제약 (이 레포에서 확인된 사실)

| 도구 | 용도 | 실측 제약 |
|---|---|---|
| `xcrun simctl` | 부팅·설치·실행·종료·스크린샷 | `simctl push`의 content-available 주입은 **iOS 26 시뮬레이터가 거부**(RequestDenied) → 사일런트 푸시 수신은 항상 실기기 잔여 |
| computer use (orca CLI) | Simulator.app 화면 내 UI 조작 | **좌표 클릭은 불신뢰(실측) — AX 액션(AXPress) 기반으로만 조작**할 것. 검수 시작 전 `computer-use` 스킬을 로드해 현재 CLI 사용법을 확인 |
| 시스템 메뉴 조작 (System Events) | Simulator 메뉴 동작 — Device ▸ Lock(잠금화면 LA 확인의 표준 수단), Home 등 | **Mac 화면이 잠겨 있으면(ScreenIsLocked) AX 기반 조작이 전면 불가** — simctl 스크린샷만 가능. 검수 시작 전 잠금 상태를 확인하고, 잠겨 있으면 진행하지 말고 보고 후 대기 |

추가 실측 규약:

- **Mac 화면 잠금 중 대체 경로 (2026-08-24 실측)**: 잠금 중에는 System Events·orca 모두 창 AX 트리가 비어 조작 불가지만, **XCUITest 하니스는 성립한다** — 스크래치 Tuist 프로젝트(더미 host 앱 + `.uiTests` 타겟)에서 `XCUIApplication(bundleIdentifier: "com.atcha.iOS.v2")`로 앱을 구동하면 XCTRunner가 시뮬레이터 디바이스 내부에서 이벤트를 주입하므로 잠금·AX와 무관하다. 증적은 `XCUIScreen.main.screenshot()`을 호스트 경로에 직접 기록(시뮬레이터 프로세스 = 호스트 FS 공유). 시스템 권한 알럿은 `XCUIApplication(bundleIdentifier: "com.apple.springboard")`의 버튼으로 처리하고, **알람 등록 검수는 알림 권한 알럿 응답까지 등록 UseCase가 대기하므로 배너 표출까지 알럿을 반복 소거**해야 한다. 엣지 스와이프 백(좌표 드래그)·셀 스와이프(`swipeLeft`)도 이 경로로 신뢰 가능 — AX 좌표 클릭 불신뢰 제약의 대체다. 한글 `typeText` 입력도 성립.
- Simulator.app의 AX 트리가 응답하지 않으면(창 열거 0·entire contents 타임아웃) `killall "System Events"` 후 재시도, 그래도 안 되면 Mac 잠금 상태부터 확인할 것(잠금이 원인인 경우가 많다).
- **위치 권한 알럿 자동화 함정 (2026-08-24 실측)**: 허용 버튼을 `label IN {"앱을 사용하는 동안 허용", "한 번 허용", ...}` 류의 다중 라벨 firstMatch로 누르면 **"한 번 허용(Allow Once)"이 눌린다** — 그 세션은 정상 동작하지만 재실행부터 권한이 소멸하고, 이후의 위치 재조회(`CLLocationUpdate.liveUpdates`)는 **권한 알럿 재표출 없이 nil 업데이트 1건 후 즉시 종료**된다(→ 앱은 unavailable 처리, 증상이 "위치가 조용히 안 잡힘"으로 보여 원인 추적이 어렵다). 허용 검수는 라벨을 **"앱을 사용하는 동안 허용"/"Allow While Using App"으로 한정**할 것.
- **위치 주입 (2026-08-24 실측)**: While-Using 정식 허용 + 검수 전 `xcrun simctl location <udid> set <lat>,<lon>`(정적 1회)이면 앱 시작 조회뿐 아니라 **재조회 스트림(검색 프리필·홈 재조회 등)에도 픽스가 도달**한다. 반면 Allow Once로 오염된 상태에서는 `location start`(waypoint 연속 시뮬레이션)·`set` 반복 펌프·XCUITest의 `XCUIDevice.shared.location` 어느 것으로도 구제되지 않는다 — 위치가 안 잡히면 주입 수단을 바꾸기 전에 **권한 상태부터 의심**할 것(`simctl privacy grant location <bundle-id>`로 확정 부여 가능).

- **강제 종료 재현은 `xcrun simctl terminate`** — 앱 스위처 스와이프 자동화 불필요.
- **LA dismiss 검수는 DEV dismiss 토글 사용** — 잠금화면 스와이프 삭제 자동화가 불안정해서 그 용도로 만들어진 수단(플로팅 디버그 메뉴의 dismiss 기록 토글, `devToggleDismissedByUser`)을 쓴다.
- **막차 변경 주입은 DEV 플로팅 "변경" 버튼** (SceneDelegate) — 앞당김/늦춤/운행 종료. actionable 경로가 필요하면 늦춤 먼저 → 앞당김 순서로 주입한다(실측 관례).
- **시간 경과는 실대기(sleep)로 수행.** 대기가 과도해지면(예: 자동 소멸 +10분) 데모 출발 시각·유예 상수를 **DEV 한정으로 단축**하는 것을 허용한다 — `DevDemoFallbacks` 관례(검수용 임시 우회 파일)와 동일한 취급.
- 다크/라이트, 시각 고정이 필요하면 `simctl ui appearance`·status bar override 사용 가능.

## 표준 시나리오 빌딩 블록 (조합해서 검수 시나리오를 구성)

| 블록 | 수행 |
|---|---|
| 준비 | Mac 화면 잠금 상태 확인 → DEV 빌드 설치·실행 (`simctl install`/`launch`) |
| 알람 등록 | 홈 → 검색 → 데모 경로 선택 → "알람 등록하기" (AXPress 시퀀스, 권한 팝업 허용 포함) |
| 변경 주입 | DEV 플로팅 "변경" 버튼 → 앞당김/늦춤/종료/dismiss 토글 |
| 잠금화면 확인 | Device ▸ Lock → `simctl io booted screenshot` (LA 상태 증적) |
| 백/포그라운드 전환 | Home 메뉴 → 재실행 (포그라운드 복귀 sync 트리거) |
| 강제 종료·재실행 | `simctl terminate` → `simctl launch` |
| 발화 대기 | 알람 시각까지 실대기 → 발화 화면 스크린샷 → "확인" AXPress |

## 증적 규약

- 스크린샷은 단계마다 저장 — 레포에 커밋하지 않는 위치(세션 스크래치 디렉터리 등)에 `p{phase}-{step}-{설명}.png` 형식으로. 보고에 경로를 명시한다.
- 최종 보고는 표로: **검수 항목 / 기대 / 관찰 / 판정(통과·실패·자동화 불가) / 증적 파일**.
- "자동화 불가" 판정은 사유(위 실측 제약 중 무엇에 걸렸는지)와 함께 실기기 잔여로 이관한다.

## 게이트 의미

- **자동 검수 (블로킹)**: 증적 보고까지 완료해야 다음 Phase 진행. 판정에 "실패"가 있으면 수정 후 재검수.
- **실기기 잔여**: 사용자 확인 대기 목록에 기록하고 진행한다 — 단, 프롬프트에 "불가 시 분기"가 명시된 항목(예: stopIntent의 강제 종료 시 실행 여부)은 **보수적 가정 쪽으로 진행**하고 실기기 결과로 확정하며, 결과를 해당 프롬프트에 기록한다. 명시가 없는 잔여 항목은 머지 전 사용자 확인을 요청한다.

## 항상 실기기 잔여인 항목 (시뮬레이터 재현 불가 실측·원리)

- 사일런트 푸시(content-available) 수신 — simctl 주입 거부, 실서버+실기기로만
- 강제 종료 상태에서의 stopIntent(LiveActivityIntent) 실행 여부 — 시뮬레이터의 프로세스 깨움 semantics는 참고값
- AlarmKit 발화의 무음 모드·집중 모드 관통
- Dynamic Island 실물 표시 품질(시뮬레이터 렌더는 참고값), Apple Watch 미러링
